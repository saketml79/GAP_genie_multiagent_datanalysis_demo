Genie Agents + Supervisor Agent: One Coordinated Supply Chain Team

Genie One reasons across the entire Genie Ontology. A Genie Agent acts as a domain specialist that answers SQL-grounded questions for Demand, Inventory, Logistics, Supplier Risk or Executive Reporting. The Supervisor Agent breaks a cross-domain business question into the right sub-questions, routes them to those specialists, and synthesizes their results into one unified executive answer.

Reads the whole ontology

Genie One

Agentic Genie over the full Genie Ontology

It reasons in agent mode across everything in the Genie Ontology, including Domains and UC Pages, so policy and definitions reach it directly with no workarounds.

question→search ontology→reasoning→answer

It is only as good as the curation behind it. On an uncurated ontology it guesses too.

Genie Agent

A domain specialist

It turns a natural-language question into SQL, using reasoning to choose the right tables, filters and formulas from the Unity Catalog semantic layer, then runs the query.

question→reasoning→SQL→result

It can’t read UC Pages, so policy reaches it through SQL functions and reference tables.

Supervisor Agent

Coordinates tools

It breaks a cross-domain question into sub-questions and calls the right tools: the five Genie Agents and SQL functions. Then it combines the results into one executive answer.

question→plan→call tools→one answer

It has no page or domain tool, so it sees the ontology only through its tools.

A single executive question asks for all 10 primary ground-truth metrics and every measure in every metric view across the 5 domains, including Cost of Disruption and the Q1 target. 27 of the 45 benchmark tests are taken from it.

I also need our current fill rate, how many inventory positions are sitting below safety stock in the West region, how many unique SKUs are affected, what is our days of supply for those at-risk items, and how many SKUs are completely stocked out. On the vendor side: what percentage of vendors delivered late in August, how many purchase orders were late out of total, what is the average lead time variance, and what are the total vendor SLA penalties we have incurred? Bring it all together as our total Cost of Disruption by region for August 2026 — cancelled revenue, at-risk backorder revenue, wasted freight on late shipments, and supplier penalty exposure in one number per region. Are we going to miss our Q1 service-level targets, and what are the top actions we should take?”

Business words vs column names

The prompt uses the language a CFO would use, which never matches the schema.

  • revenue→total_amount
  • fill rate→service_level_pct
  • vendor→supplier
  • Cost of Disruption→not in any table

Each iteration adds one standard UC / Genie capability to close this gap.

No silent gaps. If the Supervisor or a domain agent can’t find a metric the prompt asks for, it must say NOT_FOUND or NOT_UNDERSTOOD. A missing number always counts as a miss, which keeps the scoring unambiguous.

Plausible SQL is easy.Correct SQL, every time, is the work.

Enterprise warehouses already hold the answers to hard business questions. AI agents still hallucinate, misread column names or write SQL that looks right and returns the wrong number.

This Databricks workshop grounds Genie in the Unity Catalog semantic layer, so Genie One, a Supervisor Agent and five domain Genie Agents answer from business truth across 23 tables and 5 business domains.

Where the Supplier Risk agent looks

suppliers supplier_lead_times supplier_orders supplier_id is_late vendor_slas

What tells it which formula the business means

Only the column names. “Vendors” could mean distinct suppliers or purchase orders, and nothing says which.
  • Column commentis_late is recorded once per purchase order
  • Example SQLVendor late % = late POs ÷ all POs, never ÷ distinct vendors
83.33%late vendors ÷ all vendors

A reasonable reading, and the wrong number. The agent counted distinct vendors instead of purchase orders. The schema never said which one the business means.

SELECT COUNT(DISTINCT CASE WHEN is_late THEN supplier_id END) * 100.0 / COUNT(DISTINCT supplier_id) FROM supplier_orders -- August 2026 filter omitted → 83.33
75.00%late POs ÷ all POs

Matches ground truth for test F02. Same tables, same columns. What changed is the governed context around them.

SELECT AVG(CASE WHEN is_late THEN 1.0 ELSE 0 END) * 100 FROM supplier_orders -- August 2026 filter omitted → 75.00

    How Genie One answers the same question

    Genie One is the standalone Databricks chat experience. Unlike the Supervisor (which calls domain agents as tools), Genie One has direct access to the Genie Ontology — the continuously-learned enterprise context layer that indexes UC Pages, knowledge snippets, metric view schemas, column comments, governed tags, and table metadata.

    When a user asks the same CFO prompt in Genie One, the system retrieves relevant ontology snippets, routes internally to the domain Genie Agents, queries Delta tables directly, and cites UC Pages and knowledge snippets in its response.     Key difference from the Supervisor architecture

    Switch the lens, and select any row to see why it matters.

    CapabilitySupervisor AgentGenie One
    OrchestrationExplicit tool calls to 5 agents and 5 SQL functionsInternal routing via the Genie Ontology

    Explicit tool calls make the Supervisor’s plan easy to audit. Internal routing means Genie One needs no tool wiring, but its routing is only as good as the ontology behind it.

    UC PagesCannot accessReads, interprets and cites them with links

    Policy that lives only in prose, like fiscal calendars, targets and critical thresholds, reaches Genie One directly. The Supervisor needs a table or a SQL function to carry the same policy.

    Knowledge snippetsNot availableRetrieved and cited (9 snippets in the live run)

    Snippets add learned business context on top of the schema. In the live run, 9 of them were retrieved and cited for the CFO prompt.

    SQL functionsCalls them as registered tools and gets structured definitionsNot available as tools

    This is the Supervisor’s bridge to UC Page policy. Genie One does not need that bridge because it reads the page itself.

    Output formatText and tablesCards, charts, embedded query links, UC Page links

    Embedded query links let a reviewer open the exact SQL behind a number. UC Page links show the policy it was checked against.
